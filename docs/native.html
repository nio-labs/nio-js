Native Acceleration Guide

nio-js achieves its incredible performance through Hybrid Execution. By combining lightweight QuickJS for fast startup and business logic with pre-compiled Rust for heavy lifting, you get the best of both worlds.

The Problem: Interpreters vs JITs

Standard V8-based runtimes like Node.js and Bun use heavy Just-In-Time (JIT) compilers. While fast at peak, JITs consume massive amounts of idle memory and suffer from "warm-up" delays. nio-js uses QuickJS, an interpreter that starts in ~13ms and uses just 14MiB of memory. However, pure interpreted JavaScript can be slow for heavy CPU loops.

The Solution: Bypass JavaScript entirely for hot paths.

How /** @native */ Works

When you build an application, the `nio-js` Oxc parser scans your TypeScript for the /** @native */ JSDoc directive.

  1. Build-Time AST Transformation: The parser strips the JavaScript implementation and replaces it with a binding to the Rust host environment (__nioNative).
  2. Runtime Execution: Calling the function invokes native, optimized Rust machine code instead of interpreting JS bytecodes.
  3. Zero-Overhead Routing: If a native function returns static content (like a JSON payload), the `nio-js` bootstrapper evaluates it exactly once during startup and loads the raw bytes directly into the Rust HTTP router cache.

This means your hot routes never enter the JavaScript engine at all.

Example: CPU-Heavy Loops

Consider a tight mathematical loop that would normally choke an interpreter:

import { get } from 'nio.js';

/** @native */
function cpuIntensiveTask(): string {
  // In development, this fallback runs.
  // In production, nio-js intercepts this and runs the Rust-optimized equivalent!
  let value = 42;
  for (let i = 0; i < 100_000; i++) {
    value = (value * 1664525 + 1013904223) | 0;
  }
  return value.toString();
}

get('/cpu', () => cpuIntensiveTask());

Example: JSON & Static Caching

You can also use this for complex JSON structures that don't change per-request, instantly beating standard JSON serializers:

/** @native */
function generateLargePayload(): object {
    return {
        message: "Hello World",
        items: Array.from({ length: 20 }, (_, i) => ({ id: i, name: `item-${i}` }))
    };
}

get('/json', generateLargePayload());

Crushing the Benchmarks

Because of native offloading and static router caching, nio-js completely destroys traditional JIT runtimes in bare-metal benchmarks (WSL2 Linux, Intel Core Ultra 5):
